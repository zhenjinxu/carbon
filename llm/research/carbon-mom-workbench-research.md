# Carbon MOM 个人工作台研究与成熟方案对标

> 状态：研究基线（2026-08-28）  
> 结论性质：能力模式对标，不把未核实的厂商产品细节当作 Carbon 事实。

## 1. 研究结论

成熟制造运营产品普遍把“人的待办”和“现场/业务事实”分开，再通过统一入口关联：

1. 角色化入口：操作员、工艺、采购、质量、主管看到的队列不同，但都围绕当前责任、异常和下一步动作组织。
2. 例外优先：优先呈现逾期、阻塞、质量风险、库存短缺和审批，而不是只展示静态 KPI。
3. 业务对象可追溯：任务、消息和活动必须链接回工单、物品、BOM、工艺路线、库存或单据。
4. 事件驱动：业务变更产生事件，通知和搜索可以异步处理；关键业务写入仍由原事务保证。
5. 可配置而非复制：工作台是聚合视图和行动入口，权威数据仍在 ERP/MES 业务模块中。

## 2. 能力模式对标

| 对标对象 | 可借鉴模式 | Carbon 的取舍 |
|---|---|---|
| SAP 制造/业务工作中心 | 按角色、责任和异常组织工作队列；从任务回到业务对象 | 借鉴“责任队列 + 深链”，不复制复杂产品层级 |
| Siemens Opcenter | 以制造执行上下文连接工序、资源、质量和现场状态 | 借鉴“现场事实与执行状态关联”，保留 Carbon ERP/MES 的对象模型 |
| 用友制造运营 | 将组织、审批、消息、待办和业务应用放入统一工作入口 | 借鉴统一待办和组织权限，避免另建一套用户体系 |
| 金蝶制造云 | 以异常、预警、协同和移动入口缩短处理路径 | 借鉴“异常优先 + 快捷处理”，首期聚焦 Items 可验证范围 |
| 通用 MOM/MES 平台 | 计划、执行、质量、物料和设备状态形成闭环 | 以 Carbon 现有模块为权威源，分阶段接入库存、采购、生产、质量、销售、会计 |

## 3. Carbon 现状与约束

- Carbon 是 Supabase/PostgreSQL 多租户 ERP/MES；`employee`、`employeeJob`、`userToCompany` 和权限行共同决定用户可见范围。
- 审计日志按公司存储在动态 `auditLog_{companyId}` 表，记录实体、操作、操作者、差异和时间，可作为合规事实源。
- 事件系统通过 PostgreSQL 触发器、PGMQ 和后台任务异步处理搜索、工作流、同步和通知；适合工作台投影，不适合替代事务约束。
- Storage 的文件元数据在 `document`，文件路径按公司和模块隔离；工作台只保存引用和深链，不复制附件。
- 物品模块已经覆盖零件、材料、工具、消耗品及物品组、尺寸、表面处理、等级、形状、物质、类型等配置。

## 4. 不做的事情

- 不把工作台做成第二套物品、库存或工艺主数据。
- 不允许客户端传入公司 ID 后绕过服务端权限；每个 loader/action/service 都必须显式公司范围和权限校验。
- 不把异步投影成功当作业务写入成功；投影失败必须可重试、可观测、可补偿。
- 不因名称、缓存或单条事件推断业务事实；活动必须来自已验证的审计/领域事件或显式任务。
